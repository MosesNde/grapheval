# grapheval

Replication package for a study of evaluation protocol and graph encoding in
vulnerability detection with code property graphs. A citation will be added here
on publication.

The study measures two methodological choices that papers in this area do not
report — how the data is split, and the training configuration — and shows they
move results more than the architectural differences between published systems.

## What is here

| path | contents |
|---|---|
| `scripts/` | every training, ablation and analysis script used in the paper |
| `splits/` | the split definitions for all three protocols, with their audits |
| `results/` | every run artifact the paper's numbers are computed from |
| `corpus/` | the corpus manifest: function id, label, repository, commit, clone family |

## What is not here, and why

**The graph cache (59 GB).** Code property graphs for 131,903 functions, with
frozen GraphCodeBERT node features. This is *derived* data, regenerated by
`scripts/build_dataset_*.py` from the public source corpora, so shipping it
would be redundant. Regenerating it requires Joern 4.0 and roughly a day of
wall time.

**The source corpora.** BigVul, CVEfixes and Devign are public; cite them from
their own distributions rather than this repository.

**Model checkpoints.** Not required to reproduce any number in the paper. Every
reported figure is computed from the JSON files in `results/`.

## Reproducing the paper's numbers without retraining

All reported figures derive from `results/*.json`. Two file suffixes matter,
and which one a number came from is load-bearing throughout the paper:

- `*_stage1.json` — five-fold ensemble. Read `["ensemble_mean_only"]["roc_auc"]`;
  `["per_fold_roc_auc"]` holds the individual members.
- `*_single.json` — one model on the whole training partition. Read
  `["single_model"]["roc_auc"]`.
- `*_fullsingle.json` — one model on the whole partition using the *default*
  recipe, the controlled arm for the ensembling comparison.
- `*_ensnew.json` — five-fold ensemble using the *selected* recipe.

Tag grammar: `{protocol}-{backbone}[-e{edges}][-rev][-s{seed}][-{tag}]`, where
protocol is `random`, `group` or `repo`; `-rev` means edges are additionally
traversable in reverse; `-euntyped` collapses the four relation types.

**Statistical conventions.** The seed is the unit of replication; comparisons
are paired t-tests over five seeds. The five folds inside a run share a training
partition and a seed and must not be pooled as independent observations.
`group-gat-s2` is excluded from the five-fold `group` cell: it is a reduced-batch
rerun after a CUDA failure and is not comparable.

## Retraining from scratch

1. Obtain BigVul, CVEfixes and Devign from their original sources.
2. `scripts/build_dataset_*.py` to parse with Joern and cache node features.
3. `scripts/make_splits.py` to regenerate the split definitions, or use
   `splits/` directly for an exact reproduction.
4. `scripts/train_cwe.py` for the five-fold arm, `scripts/train_single.py` for
   the single-model arm, `scripts/train_fullsingle.py` and
   `scripts/train_ensemble_newrecipe.py` for the controlled procedure comparison.

Scripts contain absolute paths under `/home/moses`; adjust `ROOT` and `--cache`
for your environment.
